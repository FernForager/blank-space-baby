## The design (Library #14’s pick)
- **`build/library/wrong.json`: decoy sets.** Each set has an id, a name, a note and its entries, each `{w, m}` (the wrong answer and the meaning line a wrong pick shows) or `{w, from: "epl:3"}`, which takes its meaning from that card’s `means`, so a reworded card never leaves a stale copy. A card’s `k` names its set (`<deck>/<k>`, so deck files don’t change). Morg’s own `wr` on a card stays as it is and still wins.
- **Seed every set from today’s kinds**, one set per deck and kind, holding exactly the answers the kind offers today (cards in play, with `from` their own card). The pools are then identical, so every fingerprint (`card_hash`, `sorted(pool)`) and every day’s choices stay the same, and nothing goes back to the reviewers until a set is edited. Prove both before switching: a script that dumps every card’s fingerprint and `TRIVIELA.choices(card, day)` for days 1 to 365 from the old page and the new, then diffs them. They must match exactly.
- **What changes on purpose:** a new card no longer joins its kind’s pool by itself, so it never sends its kind-mates back to the reviewers. A card going out no longer removes its answer from anyone’s decoys. Answers join a set only when Morg (or the desk) adds them, which shows which cards go back to the reviewers.

## Where the code is
- **The page’s draw** (`build/template.html`, `choices()` near line 797): it builds candidates from `D.cards` of the same `k` (cards in play), ranks each by `hash('triviela choices ' + day + ' ' + id + ' ' + w)`, takes the first pair that doesn’t clash (`D.clash`, the deck’s `groups`), and falls back to the deck’s other kinds when a kind has too few. Candidates are card objects, and a wrong pick shows the candidate’s own `m`. Swap the candidates for the set’s entries (and the fallback for the deck’s other sets), keeping the same `{w, m}` objects, the same hash, `ok()` (clash and `seen`) and the plural rule. The build passes the sets to the page as a new `__WRONG__`.
- **The build** (`build/build.py`): `wrong_pool()` reads the sets, so `fingerprint()`, `card_hash()`, the “not enough same-kind wrong answers” check and `vet.py`’s view all follow. Check every set for house style (curly quotes, no semicolons, 22 characters, a meaning of 40 at most).
- **drawcheck** keeps its own copy of the rule on purpose (`POOLS` from `B.wrong_pool`): update it to the sets, not by copying the page’s code.
- **tools/vet.py** `carry()` assumes a card going out shrinks its kind-mates’ pools. With sets it no longer does: simplify it, keeping its oks as before.
- **tools/library.py and the Card Room**: the wrong-answers pool and the Kinds view become the sets. In the room, Morg edits a set (add or remove an entry, write its meaning, rename it) and moves a card to another set. Each save goes to the room’s database (a new `sets/<id>` collection), and `apply` writes `wrong.json` and lists the cards whose decoys changed (their fingerprints change, so they go back to the three reviewers by themselves). The new-card sheet’s “Kind” becomes “Wrong answers from”, with a toggle to add its answer to that set.
